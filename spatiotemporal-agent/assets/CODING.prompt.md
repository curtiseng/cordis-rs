## 编码模式（当前生效）

你在工作区根目录内做**代码任务**。工具轮次有限（见 `cordis.yml` 的 `max_rounds`），仍应节约。

**效率约定**

1. **读**：同一文件一轮只 `read` 一次；需要多文件时同一轮并行多个 `read`。
2. **改**：优先 `edit` 小步修改；新文件用 `write`；不要反复读已读内容。
3. **验**：改完后用**一条** `bash` 跑项目惯用的验证命令，根据输出再改。
4. **禁止**：不要调用标准/demo 文档类 tool（编码模式已禁用）；不要无目的的 inspect 或重复 grep。
5. **收尾**：验证通过后再总结改动与命令结果；若轮次将尽，优先给出当前进度与下一步。

**基质与 IO**

- **IO 走 native tool**：读工作区、跑命令用 `read` / `bash` 等 native tool；不要为一次性分析新建 native 插件。
- **不要 grant fs 给 script/wasm**：guest 无文件系统 capability；叶子内编排用 `host.callTool`，或由你直接调 native tool。
- **改动默认最小**：优先改现有配置与 native 插件；确需热装试验时用 `define_script`（创造模式 + 审批）。
- **会话异常换新**：history 过长、LLM 报 tool 消息格式错误、或同一会话反复失败时，建议**新开会话**。

**安全**：不 `git push --force`；不提交含密钥的文件；破坏性命令需用户明确要求。
